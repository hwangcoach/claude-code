# lecture-site: 원고 하나 → 네 면의 강의 사이트

강의 하나를 **마크다운 원고 한 벌**로 쓰고, 그 원고에서 다섯 종류의 쪽을 만든다.

| 면 | 누구를 위한 것 | 만들어지는 것 |
|---|---|---|
| 홈 | 링크를 받은 사람 | 히어로 · 장 목록 · 네 면 미리보기 |
| 본문 | 혼자 읽는 사람 | 장마다 한 쪽: 꼭지 목록(scrollspy) · 도판 · 각주 근거 · 「조건과 한계」 |
| 발표 덱 | 강의실 청중 | 1920×1080 단일 HTML. 발표자 노트(N), 전체 화면(F), 장 전환 wipe · 같은 꼭지 carry · 단계 등장 |
| 책으로 보기 | 출력해 두고 볼 사람 | 권 → 장, A5 쪽으로 자동 조판 · 넘겨 보기 · 인쇄하면 PDF |
| 근거 | 숫자를 확인하려는 사람 | 근거 ID별 주장 · 종류 · 출처 · 확인일 · 쓰인 곳 |

원본 사이트 분석(구조, 글꼴, 색, 움직임 값)은 `references/site-anatomy.md`에 있다. 디자인을 바꾸거나 "왜 이렇게 생겼나"를 설명할 때 읽는다.

## 전체 흐름(4단계, 단계마다 사용자 확인)

강의는 사람 앞에 서는 일이라 방향이 틀리면 뒤의 작업이 모두 버려진다. 그래서 1·2단계 끝에서는 반드시 사용자 확인을 받고 넘어간다. 사용자가 "알아서 끝까지"라고 하면 확인 없이 진행하되, 내린 결정을 기획서에 적어 둔다.

### 1단계 · 주제 잡기
`references/planning-guide.md`의 「1단계」를 따른다. 청중·문제·바뀔 행동·길이를 묻고(이미 대화에 있으면 묻지 않는다), 한 줄 약속이 다른 **주제 후보 3개**를 내놓는다. 사용자가 고르면 다음으로 간다.

### 2단계 · 강의 기획
1. 강의 폴더를 만든다: `python3 <이 스킬>/scripts/build.py new <폴더> --title "제목" --author "이름"`
   (폴더 위치를 사용자가 말하지 않았으면 현재 작업 폴더 아래 강의 이름으로. Obsidian 볼트라면 `01. Projects/` 아래)
2. `plan.md`를 채운다: 한 줄 약속, 청중, 핵심 질문, **권 → 장 → 꼭지** 구성, 꼭지마다 그림 형식과 필요한 근거, 시간표.
3. 기획서를 보여 주고 확인받는다. 근거가 필요한데 아직 없는 사실은 「근거 계획」에 "할 일"로 남긴다.

### 3단계 · 원고 쓰기(마크다운)
형식은 `references/markdown-spec.md`, 문장 규칙은 `references/writing-guide.md`. 둘 다 읽고 쓴다.
1. `sources.md`부터: 기획서의 근거 계획을 조사해 근거 ID로 정리한다. 웹 검색이나 사용자가 준 자료로 확인한 것만 적고, 확인한 날짜를 쓴다. 찾지 못한 사실은 본문에서 빼거나 "확인하지 못했다"고 쓴다. **수치를 지어내지 않는다.** 이 사이트의 신뢰는 근거 쪽에서 나오기 때문이다.
2. `chapters/NN-<id>.md`: 장마다 도입 장면 → 꼭지(주장 제목 + 그림 1~2개 + 설명 + 조건과 한계).
3. `lecture.md`의 권 제목(vol1, vol2 …)과 히어로 문구를 채운다.
4. 그림을 고른다. 데이터는 선언형 그림(`stat · bars · stack · sankey · compare · flow · timeline · list · table · terminal · statement`)으로 그린다. 장면·비유가 필요한 곳(장 도입, 강의 표지, 개념 비유)에는 삽화(`type: illust`)를 둔다. 삽화는 강의 전체에 3~8장 정도가 알맞다. 데이터를 삽화로 그리지는 않는다(숫자는 이미지 생성기가 틀리게 그린다).
5. 삽화를 만든다: `python3 <이 스킬>/scripts/illust.py gen <폴더>`. ChatGPT 이미지(codex CLI)로 생성한다. 실패하면 이유와 함께 `illustrations.md`에 프롬프트와 저장 경로를 적어 주므로, **그 시트를 사용자에게 보여 주고** ChatGPT에서 직접 만들어 저장해 달라고 한다. 삽화가 없어도 빌드는 되고 점선 「삽화 자리」가 들어간다.
6. 덱 초안을 뽑는다: `python3 <이 스킬>/scripts/build.py draft-deck <폴더>`. 그다음 `deck.md`의 스크립트를 **구어체로 다시 쓴다**. 초안은 본문 문장을 잘라 붙인 것이라 그대로 읽으면 어색하다(작성 규칙은 writing-guide의 「덱」).
7. 점검: `python3 <이 스킬>/scripts/build.py check <폴더>`. 「확인할 것」이 0건이 될 때까지 고친다(없는 근거 id, 쓰지 않은 근거, 그림 오류, 스크립트 없는 장, 아직 없는 삽화).

### 4단계 · 사이트 빌드
1. `python3 <이 스킬>/scripts/build.py build <폴더>` → `<폴더>/site/index.html`
2. 확인: 정적 서버로 연다(`python3 -m http.server -d <폴더>/site`, Claude Code 데스크톱이면 preview로). 쪽마다 콘솔 오류, 휴대폰 폭(375px) 가로 넘침, 덱 전환, 책 쪽 넘침을 본다. 브라우저나 OS가 「동작 줄이기」 설정이면 움직임이 꺼진다. 이럴 때 덱은 `?motion=1`을 붙여 시험한다.
3. 배포는 사용자가 원할 때만 한다(Vercel·Netlify·GitHub Pages 어디든 `site/` 폴더를 그대로 올리면 된다).

### 화면에서 직접 고치기(편집 모드)
사용자가 결과물을 보면서 직접 고치고 싶어 하면(「화면에서 고칠래」, 「직접 수정」, 「이 슬라이드 지우고 싶어」 등) 편집 모드를 띄워 준다.
1. `python3 <이 스킬>/scripts/build.py serve <폴더> [--port 5180]` → `http://127.0.0.1:5180/`
   (Claude Code 데스크톱이면 `.claude/launch.json`에 이 명령을 넣고 preview로 연다. 서버는 백그라운드로 계속 돈다.)
2. 사용자에게 이렇게 알려 준다:
   - 본문·근거·홈: 문단·제목·그림·조건과 한계·근거 블록을 **누르면** 오른쪽에 편집 창이 열린다. 그 블록의 마크다운 원고를 고치고 저장(⌘/Ctrl+Enter)한다.
   - 덱: 클릭은 「다음 장」이므로 **E 키**(또는 왼쪽 아래 「이 장 편집」)로 지금 장을 연다.
   - 같은 창에서 **삭제 · 위로/아래로 · 아래에 추가**(문단, 소제목, 그림, 삽화, 조건과 한계, 새 꼭지 / 새 슬라이드 / 새 근거)를 한다. 꼭지 제목을 열면 「꼭지 전체」 삭제·이동도 나온다.
   - 왼쪽 아래 편집 막대: 「되돌리기」(마지막 저장부터 하나씩), 「편집 끄기」(링크를 눌러 읽기), 「확인할 것 N건」(빌드 경고).
3. 저장하면 원고 파일이 바뀌고 사이트를 다시 만든 뒤 화면이 새로 고쳐진다. Obsidian에서 원고를 직접 고쳐도 몇 초 안에 화면이 따라온다. 바꾸기 전 파일은 `<폴더>/.edit-history/`에 남는다.
4. 편집 결과물은 `<폴더>/.site-edit/`(편집 표식이 들어간 사본)이다. 배포용은 끝나고 `build`로 따로 만든다(편집 표식·편집기 없음).
- 사용자가 화면에서 고친 뒤 Claude에게 다음 작업을 맡기면, 원고 파일이 바뀌었을 수 있으니 **고치기 전에 파일을 다시 읽는다.**
- Cowork에서는 사용자의 브라우저가 Cowork 안의 서버(127.0.0.1)에 닿지 않아 편집 모드를 쓸 수 없다. Cowork에서는 사용자가 말로 고칠 곳을 알려 주면 Claude가 원고를 고치고 다시 빌드한다. 편집 모드는 Claude Code(내 컴퓨터)에서 쓴다.

## 빌더가 알아서 하는 것(손으로 하지 말 것)
- 장마다 각주 번호를 1부터 다시 매기고 장 끝에 「이 장의 근거」를 붙임 · 근거 쪽에 쓰인 곳 역링크
- 그림을 넓은 판(1760)과 좁은 판(900, 휴대폰) 두 벌로 그림 · 같은 그림을 본문·덱·책에 함께 씀
- 덱 전환 선택: 장이 바뀌면 wipe, 같은 꼭지의 glance → explain이면 carry(같은 이름의 행·카드가 제자리로 옮겨 감), 나머지는 0.3초 디졸브
- 권 표지 SVG, 책 차례의 쪽 번호, 홈의 미리보기

그림이 선언형 형식(`stat · bars · stack · sankey · compare · flow · timeline · list · statement · table · terminal · image · illust`)으로 안 되면 fig 블록 안에 `<svg …>`를 직접 쓴다. viewBox는 `0 0 1760 H`로 하고, 덱 색 토큰을 쓴다.

## 바꾸기 쉬운 곳
- 사이트 색: `assets/tokens.css`의 `--primary`, `--primary-hover` (나머지 회색 단계는 그대로 두는 편이 낫다)
- 덱 색: `assets/deck.css`의 `:root`, 그림 색: `scripts/figures.py`의 `C`
- 전환 시간: `assets/deck.js`의 `T`
- 글꼴: 기본은 Pretendard CDN. 오프라인 강의장이면 woff2를 `site/assets/`에 두고 tokens.css에 @font-face를 추가한다.

## Cowork와 Claude Code 모두에서
- 표준 라이브러리 Python 3만 쓴다(PyYAML, npm 불필요). 외부 JS 라이브러리도 쓰지 않는다(움직임은 Web Animations API).
- 경로는 이 스킬 폴더 기준이다. Cowork에서는 결과 폴더를 사용자가 볼 수 있는 출력 위치(outputs)에 둔다.
- 예제 강의: `examples/four-faces/`. 편집 모드를 시험할 때는 예제를 사본으로 복사해서 띄운다(예제 원고가 바뀌지 않게). 형식이 헷갈리면 이 폴더의 파일을 먼저 본다(`build.py build examples/four-faces --out /tmp/demo`로 바로 빌드됨).

## 이미 있는 강의를 고칠 때
원고(md)만 고치고 `build`를 다시 돌린다. `site/`는 매번 통째로 다시 만드니 손으로 고치지 않는다. 덱만 바꿀 때는 `deck.md`만 고친다. `draft-deck --force`는 기존 deck.md를 `.bak`으로 옮기고 새로 뽑으므로, 다듬어 둔 스크립트를 잃지 않게 먼저 확인한다.
