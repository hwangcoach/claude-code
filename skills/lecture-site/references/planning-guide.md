# 주제 잡기와 강의 기획

## 1단계 · 주제 잡기

### 먼저 알아낼 것(대화에 없을 때만 묻는다. 한 번에 4개 이내)
1. **청중**: 누구인가, 이 주제를 얼마나 아는가
2. **문제**: 청중이 지금 겪는 구체적 장면 하나
3. **바뀔 행동**: 강의가 끝나고 청중이 내일부터 다르게 할 일
4. **형식**: 길이(분), 현장·온라인, 사내·공개, 자료를 나중에 공유할지

Obsidian 볼트에서 일하면 `Core Context.md`(사용자의 재활용 축·철학)와 관련 Wiki 페이지를 먼저 읽고, 사용자의 기존 자료를 주제 후보의 재료로 쓴다.

### 주제 후보 3개를 이렇게 낸다
| | 후보 A | 후보 B | 후보 C |
|---|---|---|---|
| 제목(명사구, 12자 안팎) | | | |
| 한 줄 약속("~을 알고 ~을 바꾼다") | | | |
| 핵심 질문 | | | |
| 무엇으로 증명하나(근거 종류) | | | |
| 위험(근거 부족, 너무 넓음 등) | | | |

후보 셋은 **각도가 달라야** 한다. 예를 들어 같은 소재를 "원리", "실습", "사례 비교"로 나눈다. 추천 하나를 이유와 함께 맨 앞에 둔다.

좋은 주제는 제목만 봐도 숫자나 대상이 보인다. "토큰 제대로 아끼는 법"은 무엇을(토큰) 어떻게(아끼는 법) 하는지 다 보인다. "AI 활용 전략"은 아무것도 약속하지 않는다.

## 2단계 · 강의 기획(plan.md)

### 구성 원칙
- **권 → 장 → 꼭지**. 꼭지 하나 = 주장 하나 = 그림 1~2개 = 덱 장 1~2개.
- 장은 3~8개. 첫 장은 「여는 부분」(문제 장면과 강의 순서), 마지막 장은 「닫는 부분」(내일부터 바꿀 것 번호 목록 + 확인하는 법).
- 권은 장 2~3개를 하나의 질문으로 묶는다. 권 제목은 질문이나 질문의 답으로 쓴다("요청 한 건에는 무엇이 들어가나").
- 장 순서는 청중이 품을 질문의 순서를 따른다. 답이 다음 질문을 낳게 한다.

### 꼭지 설계표
| 꼭지 id | 주장(제목 그대로 쓸 문장, 숫자 포함) | 그림 형식 | glance → explain | 필요한 근거 |
|---|---|---|---|---|
| a-01 | 인사 한 줄에 입력 51,071토큰 | stat(grid) | 숫자 → 구성(sankey) | 직접 잰 값 1, 공식 1 |
| a-00 | (장 도입 장면) | illust | — | 없음(삽화는 근거 불필요) |

- 주장에 숫자가 들어가면 근거가 반드시 필요하다. 근거를 구할 길이 없으면 주장을 바꾼다.
- glance(한눈에 보는 그림)와 explain(풀어 보는 그림)의 행 이름을 맞춰 두면 덱에서 carry 전환이 걸린다.

### 시간 어림
- 덱 한 장에 1~1.5분, 장 표지 20초. 60분 강의면 덱 35~45장.
- 「더 깊이」 꼭지(`.deep`)는 시간이 모자랄 때 `?core=1`로 빼고 발표한다.

### 기획서 확인받기
기획서를 보여 줄 때는 약속 한 줄 + 장 목록 + 근거가 아직 없는 꼭지만 짧게 요약한다. 확인받을 것은 "이 순서와 범위로 원고를 써도 되는가" 하나다.
