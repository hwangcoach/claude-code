분석한 덱은 슬라이드 70장을 한 파일에 담았습니다.[^O-002] 전환은 아무렇게나 고르지 않고 장과 꼭지의 관계로 정해집니다.

## 전환은 세 가지뿐이다 {#c-01}

```fig c-01-a
type: bars
unit: 초
steps: yes
- 디졸브 | 0.3 | 0.3
- 그림 이어 가기 | 0.6 | 0.6
- 장 바뀜 와이프 | 0.9 | 0.9 | hl
caption: 전환 세 가지와 걸리는 시간
```

기본은 두 장이 동시에 0.3초 동안 겹쳐 바뀌는 디졸브입니다.[^O-007] 장이 바뀌면 새 장이 왼쪽에서 오른쪽으로 0.9초 동안 닦아 들어오고, 경계에 구리색 선이 함께 지나갑니다.[^O-007] 같은 꼭지의 한눈 그림에서 설명 그림으로 넘어갈 때는 두 그림에 함께 있는 요소가 제자리로 0.6초 동안 옮겨 갑니다.[^O-007]

### 전환을 고르는 기준

```fig c-01-b
type: compare
steps: yes
- 디졸브 | 0.3초 | 뒤로 갈 때와 대부분의 장
- 그림 이어 가기 | 0.6초 | 같은 꼭지의 한눈 그림에서 설명 그림으로
- 장 바뀜 와이프 | 0.9초 | 장이 바뀔 때, 구리색 경계선과 함께 | hl
caption: 전환은 장과 꼭지의 관계로 정해진다
```

## 단계는 한 번에 하나씩 {#c-02 .deep}

```fig c-02-a
type: statement
text: 누를 때마다 ==하나만== 새로 나온다
caption: 단계는 한 번 누를 때마다 하나씩
```

### 장이 바뀔 때 0.9초 안에 일어나는 일

```fig c-02-b
type: timeline
steps: yes
- 0초 | 새 장이 왼쪽부터 닦여 들어옴 | 구리색 경계선이 함께 지나감
- 0.6초 | 제목이 올라오며 나타남 | 아래에서 18px, 0.4초
- 0.72초 | 그림이 이어서 나타남 | 0.12초 간격
- 0.9초 | 닦기가 끝남 | | hl
caption: 장이 바뀔 때의 순서: 0초 닦기 시작, 0.6초 제목, 0.72초 그림, 0.9초 끝
```

장이 바뀌면 닦기가 시작되고 0.6초에 제목이, 0.12초 뒤에 그림이 아래에서 올라옵니다.[^O-010] 설명 그림 안의 요소는 한 번 누를 때마다 하나씩 아래에서 24px 올라오며 나타납니다.[^O-007] 발표자는 N 키로 스크립트를, F 키로 전체 화면을 엽니다.[^O-008]

:::cond 조건과 한계
- 전환 값은 덱 파일 안의 엔진 코드에서 읽은 값이고, 화면 녹화로 시간을 재지는 않았음 [^O-007]
:::

## 사이트는 명령 한 줄로 다시 만든다 {#c-03}

```fig c-03-a
type: terminal
title: 터미널
- $ python3 scripts/build.py build examples/four-faces
- 사이트를 만들었습니다: …/site/index.html
- 장 3 · 꼭지 7 · 그림 12 · 덱 17장 · 근거 11 · 권 2
- 확인할 것 없음. | hl
caption: 원고를 고친 뒤 명령 한 줄로 사이트 전체를 다시 만든다
```

원고를 고치면 사이트는 손대지 않고 명령 한 줄로 통째로 다시 만듭니다.[^O-011] 빌더는 장과 그림, 덱, 근거 수를 세고, 빠진 근거나 깨진 그림이 있으면 「확인할 것」으로 알려 줍니다.

:::cond 조건과 한계
- 터미널 화면의 숫자는 이 예제를 빌드했을 때의 출력이고, 원고를 고치면 달라짐 [^O-011]
:::
